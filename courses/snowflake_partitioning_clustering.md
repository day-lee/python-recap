# 스노우플레이크의 마이크로 파티셔닝과 클러스터링 이해 
- 도서관 책장 관리 시스템 비유 
- 파니셔닝은 마이크로 파티션인 작은 박스에 라벨을 달아 데이터를 나누어 담는 것 
- 클러스터링은 담아놓은 내부 박스에서 정렬하고 분류하는 것 
- 스노우플레이크는 이 과정이 엔진을 자동 파티셔닝, 클러스터링 되지만 연산 비용과 성능 밸런스를 맞춰얄한다.  

### 1. Micro-Partitioning
- 자동으로 책을 박스에 담아 라벨을 붙여둠 
- 전통 DB는 개발자가 날짜별로 박스(파티션)을 만들어라고 지시함
- 스노우 플레이크는 엔진이 500MB 크기의 작은 박스로 쪼갬
- 박스에는 라벨(메타데이터)가 붙음
- 1번 박스 라벨에는 2026-09-01 부터 2026-09-04까지 데이터 있고, ID는 1부터 500까지임 
- 이렇게 미리 정리를 해두어서 사용자가 2026-09-01 데이터 찾아달라고 쿼리하면 바로 1번 박스만 열어봐서 셔플링과 I/O을 줄여주는 프루닝 원리

### 2. Clustering 
- 파티셔닝으로 담긴 박스 내부에서 가나다순으로 책 정렬하기 
- 시간 지나 데이터가 들어오다가 박스 안 데이터가 섞일 수 있음
- 결국 모든 박스를 다 열어보게 됨 
- 개발자가 이 테이블은 국가 기준으로 정렬해줘라고 clustering key를 지정해주면, 박스를 다시 정리해서 1번 박스 = 한국, 2번 박스 = 미국 식으로 재포장함
- 검색 효율 증가
- Automatic clustering으로 snowflake가 알아서 해줌 
- 모니터링하면서 데이터 오염도, 백그라운드 자동 정렬 등을 함 
- 자동으로 연산할 때 비용 문제가 생길 수 있음
- 클러스터링을 켜고 끌 수 있기 때문에 비용과 쿼리 성능 이득간 트레이드오프를 고려해서 설계해야함. 성능 이득 > 연산 비용
