
# 쿼리에 있어서는 절차적 사고가 아닌 집합적 사고를 해야함. 
> 비즈니스 요구 사항 이해 -> 독립된 집합 정의 -> 연산자 선택 -> 신택스 조립 

- Table is a Set, 테이블은 수학의 집합
- Row is a Element, 행은 집합의 원소 
- 일반 프로그래밍 언어는 절차적 방식
- SQL은 덩어리 집합에 선언하는 방식. 내부에서 어떤 순서로 읽는지 사용자는 알 필요가 없고 결과 Result Set만 중요함 

- 절차적 사고: 순서대로 이걸 먼저 조인하고, 이걸 조건절로 필터링 하고...

- 집합적 사고: 최종적으로 구해야하는 정답 집합의 모양을 상상하고, 이 집합을 만들기 위한 하위 집합(sub-set)을 독립적으로 정의하고 (서브쿼리, CTE), 그 하위 집합을 교집합, 합집합, 차집합 등으로 조립 

WHERE / HAVING 조건 제시법 
- 전제 조건에서 특정 조건 만족하는 원소만 골라냄

JOIN /IN/ AND 교집합(Intersection) 
- 두 집합 간 겹치는 공통 원소 찾기 

LEFT JOIN (IS NULL)/ NOT IN/ EXCEPT 차집합(Difference) 
- 집합 A에는 있지만 집합 B에는 없는 원소 찾기 

UNION / OR  합집합 (Union) 
- 두 집합 통째로 합치기

GROUP BY 분할 (Partition) 
- 공통 특성 가진 원소끼리 방(주머니) 나누기
