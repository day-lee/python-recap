# 이터레이터, 제너레이터
대용량 파일이나 대규모 DB 조회 시 메모리를 고작 몇 KB만 쓰면서 안전하게 데이터를 스트리밍 처리하기 위함
메모리 RAM 방어 
제너레이터는 데이터를 미리 다 만들어 두지 않고 요청할 때마다 한조각씩 찍어내는 게으른 공장 

이터레이터는 next()로 하나씩 값을 꺼낼 수 있는 규칙을 가진 모든 객체
제너레이터는 이터레이터의 한 종류
제너레이터는 yield 키워드로 이터레이터 규격을 만들어서 넘겨줌

이터레이터를 직접 만들려면 클래스 선언하고, __iter__도 만들고, __next__ 메서드도 만들고 StopIteration 예외도 만들어야하는데
제너레이터는 yield 키워드로 간단하게 만들 수 있음


### return 키워드 vs yield 키워드
함수: 퇴사 vs 근무 중 연차 사용
reutrn은 값 반환하면 함수 끝낸다.  
yield는 값 하나 반환하고 함수를 일시 정지한다. pausing, freeze mechanism으로 체크포인트 역할을 하고
next()로 트리거되면 다시 yield 다음 줄 부터 실행할 수 있게 된다. 

이터레이터는 일회용 iter()로 만들고, next()로 하나씩 꺼내서 사용.
포인터가 끝까지 전진하고 나면 뒤로 돌아갈 수 없음 


### 메모리 폭발 없이 하나씩 꺼내며 카운팅 가능!
- 결과 Counter({'A': 100000000, 'B': 100000000})

이 코드에서 next()가 명시적으로 보이지 않는데도 값이 잘 계산되는 이유는 다음과 같습니다.
1. 객체 생성 단계: huge_data_generator()를 호출하는 순간에는 내부 코드가 실행되지 않고, 오직 값을 생산할 준비가 된 *제너레이터 객체만 생성*되어 반환됩니다

2. 자동 호출 단계: 이 제너레이터 객체를 Counter()에 전달하면, *Counter가 내부적으로 루프를 돌며 제너레이터의 __next__를 자동으로 계속 호출하여 값을 하나씩 빼옵니다*

3. 지연 평가(Lazy Evaluation): 2억 개(1억 * 2)의 문자열을 한 번에 메모리에 적재하는 대신, *Counter가 다음 값을 요청할 때마다 메모리에 딱 하나씩만 올려서 전달합니다*
덕분에 대규모 데이터임에도 불구하고 메모리 에러(OOM) 없이 안전하게 스트리밍 처리가 가능합니다

4. 소진: 제너레이터가 모든 값을 다 내어주고 StopIteration에 도달하면 소진(exhausted) 상태가 되어 루프가 자연스럽게 종료되고 최종 카운트 결과가 화면에 출력됩니다

def huge_data_generator():
    for _ in range(100000000):
        yield "A"
        yield "B"

from collections import Counter
my_counter = Counter(huge_data_generator()) 
print(my_counter)


### [] vs ()제너레이터  
리스트 컴프리헨션은 전체 데이터를 다 메모리에 올려버림. 한번에 만든다. 
제너레이터는 쿠폰과 같다. 유저 하나씩 꺼낼 때 쿠폰을 내밀면
메모리에 해당 데이터만 올려서 주고, 다 쓰고나서 다음 데이터로 넘어가면 이전 데이터는 지워짐. 
tuple([list]) 리스트 컴프리헨션에 튜플 메서드를 써줘야 결과값이 튜플이 됨. 괄호로 컴프리헨션 문법을 쓰면 제너레이터 문법임. 튜플은 컴프리헨션이 없음 주의 

lazy evaluation(지연평가)방식
"제너레이터는 만들 때 계산 안 하고(0초), next로 부를 때만 일한다"
제너레이터는 함수를 바로 실행하지 않고, next()함수를 호출할 때가 되어야 실제로 계산을 한다.
